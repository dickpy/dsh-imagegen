# v1.18.1 · 提示词增强与模型检测修复（#84 / #86）

## 提示词增强模型

- 修复「获取可用模型」在未保存或未配置时报 `API URL is required`：检测现在直接使用设置卡片里的草稿（渠道选择 / 自定义地址与密钥），不再只读上一次保存的结果。
- 新增「接口来源」选择：复用生图渠道（可选具体渠道，默认自动跟随默认渠道）或独立对话 API；所选渠道写入新设置项 `promptChannelId`，宿主按它解析对话端点。
- 复用渠道只列出可用于对话的 API 密钥渠道；订阅登录渠道与填写了完整接口地址的渠道会标注原因并禁用。
- 模型候选列表新增按名称筛选与数量提示，并回显检测来源；分组内新增「保存修改」按钮与未保存提示。
- 配置类错误改为结构化错误码（`prompt-url-missing` / `prompt-channel-unsupported`），由界面渲染中/英/俄文案。

## 对话模型不再跨地址复用密钥（#84）

- 填了独立对话地址但没填密钥时，请求**不带** `Authorization`；不再静默借用图像渠道的密钥发给另一个服务。界面提示「未配置对话 API 密钥」并说明原因。
- 检测结果与失败信息都会回显请求地址与密钥来源（渠道密钥 / 独立密钥 / 未配置），上游 401 不再被当成「你填的密钥无效」独占整块红字。
- 复用渠道时地址与密钥同源，行为不变。

## 建图模型检测兼容只给过滤列表的网关（#86）

- 图片检测额外探测 `<base>/models?kind=image`，并在多个候选地址之间**合并**结果而不是取第一个成功响应；严格网关拒绝该参数时回退到普通列表，不会整体失败。
- 能力识别新增三条明确判据：`kind: "image"`、`supported_endpoint_types` 含 `image-generation` / `image-edit`、嵌套 `modalities.output` 含 `image`。
- 只有图片检测带 kind 探测，`/models` 的对话模型列表保持原样（不会被 25 个生图模型污染）。

## 文档（#85）

- README 补充：第三方直接改写 profile 的 `cordis.patch.yml` 不会热更新已实例化的插件（`.volatile()` 字段由宿主设置服务推送），改完请在设置页再保存一次或重启 DSH。

`tsc --noEmit`、单元测试 74 项、remote 套件 14 项、`scripts/smoke.mjs` 全部通过；新增用例覆盖 kind 过滤探测与合并、严格网关回退、三种能力标记，以及「独立地址 + 空密钥时不复用渠道密钥」。
