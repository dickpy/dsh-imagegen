# v1.13.0 · 图片转可编辑 PPT：把视觉层真的还原出来

用户拿真实幻灯片测试后的反馈是对的：成片「只有文字，没还原图片」。这不是模型不给力，
是我们只把「文字」当成交付物，而且验收规则本身有洞。本版把视觉层补齐，并让「只有文字」不再可能被判成功。

## 视觉层改由像素测量兜底

新增 [src/ppt-visual-regions.ts](../src/ppt-visual-regions.ts)：不再依赖模型肯不肯画图形。

- 半分辨率 12 色调色板量化 + 8-邻域连通域；背景取**边框众数 index 的中位 RGB**（四角平均会把装饰页采成 `#6A6371` 这种脏色，实测踩过）
- 分类：短边 <30px → **线/箭头**；`color_spread < 8` 或 `text_share > 0.4` → **面板**（落成原生矩形，取中位色为填充，可点选改色改字）；其余 → **位图**（从原图确定性裁剪）
- 落在位图裁剪区域内的 OCR 文本行不再重复生成文本框（避免字压字）
- 整页级插画走 `editppt image edit` 的 clean base（`source_type:"imagegen"`，上游唯一许可的整页背景做法）；
  有 clean base 的页**不再叠加源图裁剪**（否则同一张插画出现两份 = 鬼影），表格/图表/照片仍按裁剪保留
- 逐页上报 `panels / bitmaps / lines / fidelity / sourceInk`，任务卡片显示「图形 10 个 · 贴图 1 个 · 视觉还原 79%」，
  低于 60% 追减低还原提示；找不到中文字体时也会告警而不是静默出空白预览

## 验收堵死「只剩文字」

- `inspectDeck` 现在区分**几何形状**与文本框（`txBox="1"` 不计入 `graphicShapes`），并识别原生表格
  （`p:graphicFrame` 里的 `a:tbl`）——之前文本框也算「原生形状」，所以白底纯文字页永远合格
- 新增拒绝原因 `visual-loss`：源图该页有真实图形（非文字墨迹 ≥8%）而成片既无贴图、又无几何形状、也无原生表格 →
  整次转换判失败并说明原因，不再静默「完成」
- 新增设置 `pptVisualMode`：`hybrid`（默认，图为主页面可用图像后端出 clean base，会消耗图像额度）、
  `regions`（零图像额度：这类页明确失败并说明原因，绝不交白卷）、`text`（只重建文字，作为对照）

## 实测（本机、真实模型、真实 editppt）

| 页面 | 修复前 | 修复后 |
| --- | --- | --- |
| 业务页（4 卡片 + 表格 + 箭头 + 照片；非文字墨迹 16%） | `shapes=0 / images=0` | 图形 10 / 贴图 1 / 视觉还原 **79%**，零图像额度 |
| 真实插画页（非文字墨迹 72%） | 只剩文字，底图丢失 | clean base 走通 + 6 个可编辑文本框，**人物不再重影** |
| 两页混排（业务 + 插画） | — | 125 s 出片：`textRuns=20 / graphicShapes=18 / pictures=2`，`acceptDeck ok` |

## 已知边界

- 表格目前是**裁剪保留**（看起来对、单元格不可逐格编辑）；原生 `tables[]` 重建是下一步。
- 面板圆角测不准，统一落 `rect`（避免上游 roundRect 半径契约违规）。
- 图像后端依赖 `~/.editppt/config.yaml` 或 Codex OAuth；两者都不可用时，图为主页面会明确失败而不是降级成文字页。
- 公式、演讲者备注、PDF/PPTX 输入仍未接入本地管线。

设计与口径见 [本地管线说明](../ppt-local-pipeline.md) 的「视觉还原层」。
