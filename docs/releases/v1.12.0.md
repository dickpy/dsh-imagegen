# v1.12.0 · 图片转可编辑 PPT：本地确定性管线

## 变化

「图片转可编辑 PPT」不再依赖无头 Agent 能否开壳、能否点审批。默认执行方式改为
**本地管线**：插件宿主进程直接驱动上游 `editppt` CLI，模型只负责一次「看图判断」。

- 每页流程：`prepare` → 文字检测 → 一次多模态判断 → 合并 manifest → `page build` →
  `page validate`（不通过最多回灌修复 2 轮）→ `contact-sheet` → `run record` → `run finalize`。
- **文字坐标只来自 OCR 测量**（`text_hints.json`），模型不再决定位置，减少幻觉与错位。
- **照片/图标区域由本机从源图裁剪**（Pillow），全程不调用任何生图 API、不产生图像费用。
- **统一验收入口**：两条驱动路径都要过同一套检查——合法 OOXML、页数一致、上游
  `validation.json.passed === true`、每页确有可编辑对象；「整页截图当幻灯片」会被拒绝，
  不再被标记成转换成功。
- **前置条件在点转换前就说清楚**：缺少可读图的聊天模型 / 未装 skill / （agent 模式）无 Agent
  运行时时，按钮禁用并给出原因，不会启动一个空转到超时的付费任务。
- **重任务超时真正生效**：看门狗现在会结束卡死的适配器并释放串行队列（此前一个卡住的
  PPT 任务会一直占住画布技能队列，后续技能全部排队）。
- 新增设置（生图配置 → 无限画布技能）：`执行方式`（local/agent，默认 local）、
  `每页并发`（1-3，默认 2）、`单页预算分钟`（默认 6）。
- 本地模式不需要：长任务开关、Agent 预设、文件/命令权限、子 Agent、审批入口。

## 修复：中文 Windows 上「所有页面都重建失败」

真实反馈：每页都报 `editppt run record 失败（退出码 1）`，尾部是
`UnicodeEncodeError: 'gbk' codec can't encode character '\u2661'`。

根因不在内容也不在模型：中文 Windows 上 Python 的 stdout 默认编码是 cp936(GBK)，
而 `validate_pptx.py` 会把**页面文字本身**打印进校验报告；幻灯片里只要出现一个 `♡`，
`print()` 就在活干完之后抛异常、命令非 0 退出，于是「已经建好并通过校验的一页」被判失败。
A/B 实测（同一页 manifest 加 `♡✨` 后重建）：

```
未修： UnicodeEncodeError: 'gbk' ... \u2661     exit=1
已修："passed": true                            exit=0
```

修法：插件给**每一次** editppt / python 子进程固定注入 `PYTHONIOENCODING=utf-8` +
`PYTHONUTF8=1`（`PYTHON_UTF8_ENV`，src/skill-config.ts），运行环境的
`doctor/setup/install` 同样注入；旧的 Agent 驱动路径在提示词里要求先设这两个变量。
回归守卫：`node scripts/ppt-utf8-env.test.mjs` 在本机 gbk 默认下同时断言
「不带修复必失败 / 带修复能打印」。

顺带说明：离线文字检测模式下，装饰符号（`♡ ✨ ⚠`）是否保留取决于模型转写；
配了 PaddleOCR token 时文字内容来自 OCR，保真度更高。

## 前提

1. 「生图配置 → 图片转可编辑 PPT」装好官方 skill 与运行环境（Python 3.10+，`editppt doctor` 通过）。
2. 「提示词增强」配置一个**支持视觉**的聊天模型（API 地址 + 模型名）。本地管线用它读每一页。
3. 可选：PaddleOCR token（文字内容与行框更准）；离线检测只提供位置与尺寸。

## 实测（Windows Desktop，2026-10-30）

- 2 页中文业务页 → 50 秒出片：第 2 页 10 个文本框 + 5 个自绘形状，`pictures = 0`，
  上游 `final/validation.json.passed = true`，验收 `acceptDeck` 通过。
- 修掉了 Windows 上 `preview.png` 渲染空白的问题：上游预览字体候选只有 macOS 路径，
  现在 manifest 会带上本机真实存在的中文字体（`preview_font`），预览可见中文；
  探测不到字体会发 warning，而不是假装成功。
- 复现脚本：`node scripts/ppt-pipeline-selftest.mjs`（stub 模型 + 真实 CLI，30 项断言）、
  `node scripts/ppt-pipeline-live-test.mjs <图片...>`（真实模型 + 真实 CLI）、
  `node scripts/ppt-chat-vision-probe.mjs <model>`（确认渠道是否接受 `image_url`）。

- 公式 LaTeX 重建、演讲者备注、PDF/PPTX 输入（仍为 1-12 张 PNG/JPEG/WebP）。
