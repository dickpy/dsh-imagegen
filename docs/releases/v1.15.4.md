# v1.15.4 · 会话里的结果图可以就地预览和保存（#62）

## 1. 修复会话内生成结果的点击无响应（#62）

会话里那张结果图之前是一个 `<a target="_blank" href="blob:…">`：桌面端主窗口的新窗口策略只放行 `http`/`https`（走系统浏览器），
其余协议一律 `deny`，于是 `blob:` 链接既不打开窗口、也不报错——悬停有「打开原图」提示，点下去毫无反应。

现在缩略图改成按钮，点击在**当前窗口内**打开灯箱：

| 能力 | 行为 |
| --- | --- |
| 预览 | 全屏灯箱显示原图（`object-fit: contain`），带尺寸与文件名 |
| 保存 | 「下载」直接 `<a download>` 落盘，保留附件名与扩展名 |
| 复制 | 剪贴板写入 PNG（JPEG/WebP 先转 PNG） |
| 关闭 | Esc、点遮罩、「关闭」按钮三种方式，焦点退回缩略图 |
| 多图 | 结果含多张时显示 `1 / 2`，左右方向键与两侧按钮翻页 |

- 灯箱走 `createPortal` 到 `document.body`，不受对话区域裁切；遮罩与配色沿用插件内既有的 lightbox 视觉（深色背景 + 白色胶囊按钮）。
- 纯客户端改动，不涉及协议、宿主路由或附件读取逻辑；`AGENT_IMAGE_API` 与既有的 `refs → blob URL` 流程保持不变。
- 旧写法在 `dsh web`（浏览器）里能"凑巧"打开标签页，因此这个坑只在桌面端暴露；改成就地预览后两端一致。

## 2. 一并带上 v1.12.0 – v1.15.0 的积累

本版是 v1.11.0 之后第一次公开发布，包含此前只存在于开发分支的改动：

- **可编辑 PPT 流水线**（v1.12.0 / v1.13.0）：宿主导出的确定性 `图片 → 可编辑 PPTX` 重建，按实测像素还原视觉层，拒绝纯文本产物；editppt / python 子进程强制 UTF-8 I/O。
- **反推提示词 + 隐藏 deck 转换入口**（v1.13.0 → 1.15.0 期间的破坏性调整）。
- **设置面重建**（v1.15.0）：`设置 → 插件` 新增「生图配置」标签页，四组子 tab 与总览条；与「设置 → 生图配置」共用同一份 controller。
- **插件详情页内配置**：渠道/密钥等配置项移入插件详情页。
- **诊断**：客户端上报实际启动的构建版本，便于排查 host/client 版本错配（正是 v1.15.3 期间那次 `ERR_MODULE_NOT_FOUND` 的事故面）。
- **设置页注册修正**：Plugins 标签页改用 DSH 真正声明的 slot 名。

详见 `docs/releases/` 下的 v1.12.0 / v1.13.0 / v1.14.0 / v1.15.0 记录。
